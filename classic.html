Case studies

Problems, decisions, results

A few stories in more detail. The numbers come from measurements made before and after each change.

105k URLs
checked to fix duplicate and uncrawled pages

Getting a long-running site indexed again

Problem
Search Console showed about 10,000 duplicate pages and 29,000 pages Google had found but never crawled. The site had no sitemap since 2019 and still sent data to the retired Universal Analytics.
Approach
Built a database-driven sitemap, cached and rebuilt in the background; made canonical URLs come from each page's own parameters instead of echoing the address; sent old URLs to their new home with permanent redirects and made deleted content return 404; moved analytics to GA4.
Result
All 105,347 sitemap URLs checked automatically and live samples matched 134 of 134. Pages indexed by Google went from about 40,000 to 115,000.
−80%
mobile home page weight on first load

Making heavy pages light

Problem
Pages were slow on phones. Some listing pages pulled 28 MB of full-size photos, blog posts carried images pasted straight into the text, and one paid business page took about 7 seconds.
Approach
Lazy-loaded everything below the fold; added an on-the-fly image resizer; converted pasted images to stored files automatically; rewrote a SQL join that rescanned 33,000 rows for each of 6,900 posts and proved the results identical on a copy of the live data.
Result
Mobile home page first paint 4.1 MB → 0.85 MB; listing page images 27.9 MB → 1.9 MB; the 7-second page now opens at once.
9 sections
searched by the assistant through tool use

An AI assistant that only answers from the site

Problem
People asked the same questions again and again (a Korean dentist nearby, a room for next month, this weekend's events) and the answers were spread across many sections.
Approach
Gave Claude search tools over the site's own data instead of letting it answer from memory; streamed answers with cards to call, map or open; logged every question with its cost; added daily limits, prompt caching and a "words not found" report so the team can see what is missing.
Result
One assistant on the portal and on every club and blog site from a single script line, plus a full-page AI search beside the normal results.
466,598
price combinations checked after a change: 0 differences

Changing a live store without changing a single price

Problem
The print store prices everything instantly in the browser. The owner wanted an internal view for quoting, and the public page should carry nothing but selling prices.
Approach
Added a build step that computes the selling prices once and publishes only those, in the same shape the page already reads, then compared the old and new page option by option in a headless run. The owner's extra view loads only after signing in.
Result
Every one of 466,598 option combinations returned the same price, and the page stayed fast.
1.4 GB
of dead tables removed, every step reversible

Unicode for a legacy database, safely

Problem
Emoji and some Korean text were lost because old columns were not Unicode, and the change was blocked by about 1,800 leftover tuning indexes.
Approach
Every data-changing script runs in one transaction with a backup, a guard against running twice and a matching rollback script, and is tested on a local copy first.
Result
Text columns moved to Unicode; 31 dead tables (about 1.4 GB, some from 2013) dropped after proving nothing used them.
